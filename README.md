# Automated Terraform Workflow

This repository provides a boilerplate for an automated Terraform workflow utilizing GitHub Actions to manage module versions, validate code, and ensure PR branches are constantly rebased onto `main`.

## Structure

- `/modules/`: Contains reusable Terraform modules (e.g., `example`).
- `/environments/`: Contains environment-specific configurations (e.g., `dev`, `staging`, `prod`) that reference the modules via versioned git tags.
- `/scripts/`: Helper scripts used by CI/CD (e.g., `update_version.py`).
- `/.github/workflows/`: GitHub Actions pipelines.

## Pipelines

### 1. Update Terraform Module Version (`bump-version.yml`)
A manually triggered workflow (`workflow_dispatch`) that allows you to bump a module version for a specific environment.

**How to run:**
1. Go to **Actions** > **Update Terraform Module Version** > **Run workflow**.
2. Provide the `environment` (dev, staging, prod), `module_name` (e.g., example), and `module_version` (e.g., v1.1.0).
3. The pipeline will automatically create a branch, update the reference in the `.tf` file, and open a Pull Request.

### 2. Automatic Rebase (`auto-rebase.yml`)
Ensures PRs are automatically rebased onto the latest `main`.
- **On PR Update:** Automatically rebases the current PR branch on top of `main`.
- **On Main Update:** Automatically iterates through all open PRs and attempts to rebase them on top of `main`. If a merge conflict occurs, the workflow will comment on the PR.

### 3. Terraform CI (`terraform-ci.yml`)
Runs on every Pull Request toward `main`.
- Validates the syntax (`terraform validate`).
- Comments the plan generated by `terraform plan` on the PR for easy review.

## Requirements

Ensure that you have granted **Read and Write permissions** to your GitHub Actions:
`Settings -> Actions -> General -> Workflow permissions -> Read and write permissions`.
